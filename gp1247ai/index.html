VFD Animation Player

< Back

This project started when I purchased a Futaba GP1247AI vacuum fluorescent display (VFD) from AliExpress. I started by designing a PCB to power the display since it needs 50V, 75V, and floating 5V power supplies. I achieved this functionality using 3 boost converters. Notably, I included an 8V boost converter for the VFD filament. 8V was applied to one side of the filament, and the other was connected to ground with a 3.3V zener diode; this provided ~5V across the filament but with a higher potential to ground as the datasheet called for. This 3.3V bias above ground is called the VFD cut-off voltage. The cut-off voltage is important to ensure the phosphors don’t glow faintly even when they are switched off.

Initially for the animation I had the idea of streaming frames so the display could be used like a computer monitor. To implement this functionality, I made a python program to convert a GIF into my own custom binary format and then made another program to send frame packets over USB CDC. On the microcontroller side I used the TinyUSB C library to help with USB communication on an STM32F407 dev board. To send frames to the display I had to read the datasheet and implement my own library so I could use DMA with the SPI transfers. I used the U8G2 C library for initial tests but scrapped due to it being too slow. After a week of fixing bugs I was finally able to successfully stream frames over USB and began planning a new PCB design with an onboard MCU. The streaming code is available here, but it’s pretty messy.

For the new revision I decided I wanted onboard flash so an animation could be loaded onto the device and then replayed without needing a program to constantly run on a PC. So the new PCB featured a 16MiB flash chip as well as an STM32F405. Additionally, the zener diode filament bias setup was swapped with a 5V isolated power supply module. Instead of wasting 1.3W of heat through the zener, the isolated power supply simply had one of its outputs floated to the 3.3V bus. I also included a tilt switch so the device could work in two orientations, and I added a 32.768 kHz oscillator and coin-cell battery for timekeeping.

With the new hardware, I implemented a clock and reworked the animation player, these modes can be selected by the switch on the front panel. The animation now streams from the onboard flash, but I kept some USB functionality. USB is now used to upload the animation from the PC and to sync, read, and calibrate the onboard RTC. After calibrating the RTC, I was able to get accuracy within ~3 seconds a month. I also designed an open-frame case in onshape.

This is the first big project I’ve done in C; previously, I’d used Rust. Now I really appreciate the simplicity of C and the greater level of support compared to Rust embedded programming. Perhaps next time I should mix in a little bit of C++ for classes and methods for classes for a bit better organisation.
